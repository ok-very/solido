# S17 — Inverse Synthesis Pipeline

> You hum. The creature learns to sing it back.

**Layer**: L5 (Organisms) + L6 (UX Shell)
**Depends on**: S13 (first organisms), S16 (normalized params), S14 (cell wiring)
**Status**: Prospect

## Goal

Build an inverse synthesis pipeline that, given a target audio recording, searches the organism DNA parameter space to find configurations that produce similar sound. This enables "sound-target mode" — the user provides a reference (mic input, audio file, or live audio), and Solido evolves organism DNA toward it. Inspired by SpiegeLib's automatic synthesizer programming, adapted for Solido's real-time generative architecture.

## Ancestry (MAKE A BABY)

MAKE A BABY had no inverse synthesis — you built patches by hand or by accident. SpiegeLib formalized the inverse problem for VST synths: target audio → feature extraction → parameter estimation → matched audio. Solido's version is different in two key ways: (1) organisms are generative, not one-shot — they produce evolving texture, not a single rendered buffer, and (2) the parameter space is DNA, not a flat knob vector. This spec bridges SpiegeLib's research framework with Solido's living system.

The Max/MSP patch relied on the composer knowing what a `cycle~ 440` sounded like and manually choosing params. Inverse synthesis lets the system learn that mapping.

## The Problem

### No path from "I want it to sound like this" to DNA

A user hearing a sound they want to reproduce in Solido has no tools. They can manually tweak cell params in a hypothetical DNA editor, but there are 30+ params per organism across 5-7 cells with logarithmic and integer-quantized scales. The search space is too large for manual exploration.

Current species parameter counts:

| Species | Cells | Numeric params | String params | Total dimensions |
|---------|-------|---------------|---------------|-----------------|
| TBLK | 2 (pattern_gen + strike_voice) | 9 | 0 | 9 |
| DRON | 2 (harmonic_bed + shimmer_layer) | 8 | 1 (filter.type) | 9 |
| MELO | 3 (arpeggiator + timbre_voice + mod_matrix) | 19 | 2 (osc.mode, filter.type) | 21 |

Even the "simple" TBLK has a 9-dimensional search space where `membrane_freq` is logarithmic [40, 800] Hz, `steps` is integer [1, 16], and `click_mix` is linear [0, 1]. A human can't efficiently search this.

### Organism audio is generative, not deterministic

Unlike a VST that renders the same output for the same params + MIDI, Solido organisms are stochastic. PatternGen produces Euclidean rhythms that are deterministic per-seed, but the overall character varies across render windows. A `strike_voice` with the same params produces the same transient each hit, but the rhythm pattern's interaction with the organism's tick timing creates variability.

Feature comparison must capture **statistical texture** — the distribution of timbral properties over time — not sample-level waveform matching. McDermott & Simoncelli (2011) showed that sound textures are defined by their statistics (mean, variance, skew, kurtosis of spectral features), not by exact waveform.

### OrganismDsp already supports headless construction

`OrganismDsp::from_dna(&dna, sr)` at `organism_dsp.rs:49` returns `Option<(OrganismDsp, SharedHandles)>` and requires only DNA + sample rate. No reactor, no audio substrate, no ring buffers needed. The returned `SharedHandles` provide real-time param control but are optional for offline rendering. This means headless rendering is almost free — we just need a thin wrapper that ticks and collects output.

## Architecture Decisions

### AD-1: Two-tier approach — evolutionary search + optional neural estimator

**Tier 1 (always available): Evolutionary search.** Population-based optimization directly in DNA space. No training data needed. Runs in ~2-5 minutes per target. Works immediately with any cell configuration.

**Tier 2 (optional, requires dataset): Neural estimator.** Trained offline on datasets generated by Tier 1's infrastructure. Predicts params in milliseconds. Specific to a cell topology — a TBLK estimator can't predict MELO params. Lives in a future S17b when `candle` inference is available.

This mirrors SpiegeLib's dual approach (GA vs deep learning) but prioritizes the evolutionary path because Solido's parameter space changes structurally (different cell compositions per organism species, and users can define new species).

### AD-2: AudioFeatureSet — 38-dimensional texture descriptor

A single `AudioFeatureSet` captures the **statistical character** of a 2-4 second audio window.

```rust
/// Audio texture descriptor — captures the statistical character of a sound,
/// not its exact waveform. Designed for comparing generative/stochastic audio.
#[derive(Clone, Debug)]
pub struct AudioFeatureSet {
    // --- Timbral shape (primary discriminator) ---
    /// 13 MFCCs averaged across frames. Captures spectral envelope shape.
    /// MFCC[0] = log energy, MFCC[1..12] = spectral shape.
    pub mfcc_mean: [f32; 13],
    /// MFCC variance across frames. Captures timbral stability vs evolution.
    pub mfcc_var: [f32; 13],

    // --- Spectral statistics ---
    /// Mean spectral centroid (Hz). Brightness.
    pub centroid_mean: f32,
    /// Variance of spectral centroid. Brightness stability.
    pub centroid_var: f32,
    /// Mean spectral flatness [0,1]. 0=tonal, 1=noise.
    pub flatness_mean: f32,
    /// Mean spectral rolloff (Hz). High-frequency energy boundary.
    pub rolloff_mean: f32,

    // --- Temporal texture ---
    /// Mean zero-crossing rate [0,1]. Noisiness/pitch indicator.
    pub zcr_mean: f32,
    /// Mean RMS energy. Loudness.
    pub rms_mean: f32,
    /// RMS variance. Dynamic range / pulsiness.
    pub rms_var: f32,

    // --- Rhythmic texture ---
    /// Detected onset rate (onsets per second). Rhythmic density.
    pub onset_rate: f32,
    /// Inter-onset interval variance (seconds²). Rhythmic regularity.
    /// Low = metronomic. High = rubato or random.
    pub ioi_var: f32,
}
```

38 dimensions total (13+13+2+1+1+1+1+1+1+1). The mean/variance pairs are critical: two organisms can have the same average timbre but very different temporal evolution. A drone has low MFCC variance; a percussion pattern has high.

**Why these features:**

| Feature group | Dims | What it captures | Weight in fitness |
|---------------|------|-----------------|-------------------|
| MFCC mean | 13 | Average spectral shape (timbre) | 0.35 |
| MFCC variance | 13 | Timbral evolution / stability | 0.25 |
| Spectral stats | 4 | Brightness, tonality, energy distribution | 0.15 |
| Temporal | 3 | Energy dynamics, noisiness | 0.10 |
| Rhythmic | 2 | Beat density, regularity | 0.15 |

MFCCs dominate because timbral shape is the strongest perceptual discriminator (SpiegeLib, Horner et al. 1993). But MFCC variance and rhythmic features are essential for Solido's generative organisms — a TBLK is defined as much by its rhythm as its timbre.

### AD-3: MFCC computation — pure Rust, zero external dependencies

Implement MFCC extraction from scratch using `rustfft` (already in the dependency tree via FunDSP). No external audio analysis libraries.

**Algorithm (for 44100 Hz sample rate):**

```
Parameters:
  sample_rate    = 44100 Hz
  frame_size     = 2048 samples (~46 ms)
  hop_size       = 512 samples (~11.6 ms)
  fft_size       = 2048
  n_mels         = 40 (mel filterbank bands)
  n_mfcc         = 13 (output coefficients)
  f_min          = 20 Hz
  f_max          = 16000 Hz
  pre_emphasis   = 0.97
  window         = Hann

Pipeline per frame:
  1. Pre-emphasis: y[n] = x[n] - 0.97 * x[n-1]
  2. Hann window: y[n] *= 0.5 - 0.5 * cos(2π * n / (N-1))
  3. FFT: X = fft(y), keep first N/2+1 = 1025 bins
  4. Power spectrum: P[k] = |X[k]|² / N
  5. Mel filterbank: E[m] = Σ_k H_m[k] * P[k], m = 0..39
  6. Log power: S[m] = ln(max(E[m], 1e-10))
  7. DCT-II: c[n] = Σ_{m=0}^{39} S[m] * cos(π * n * (m + 0.5) / 40), n = 0..12
```

**Mel filterbank construction:**

```rust
fn build_mel_filterbank(n_mels: usize, fft_size: usize, sr: f32, f_min: f32, f_max: f32)
    -> Vec<Vec<(usize, f32)>>  // sparse: Vec of (bin_index, weight) per mel band
{
    // 1. Convert f_min, f_max to mel: mel(f) = 2595 * log10(1 + f/700)
    // 2. Create n_mels+2 equally spaced points in mel space
    // 3. Convert back to Hz, then to FFT bin indices: bin = floor(f * fft_size / sr)
    // 4. For each of n_mels filters: triangular window from bin[m-1] to bin[m+1],
    //    peaking at bin[m], normalized to unit area
}
```

Storage is sparse (each mel band covers ~5-50 FFT bins). Total memory: ~2KB for the filterbank.

**DCT-II (13 coefficients from 40 mel bands):**

```rust
fn dct_ii(log_mel: &[f32; 40], n_mfcc: usize) -> [f32; 13] {
    let mut mfcc = [0.0f32; 13];
    let n = log_mel.len() as f32;
    for i in 0..n_mfcc {
        for m in 0..log_mel.len() {
            mfcc[i] += log_mel[m] * (PI * i as f32 * (m as f32 + 0.5) / n).cos();
        }
    }
    mfcc
}
```

No external DCT library needed — 13×40 = 520 multiplies per frame.

**Per-window AudioFeatureSet computation:**

```rust
impl AudioFeatureSet {
    /// Extract features from a raw audio buffer (mono, f32, 44100 Hz).
    /// Duration should be 2-4 seconds for stable statistics.
    pub fn from_audio(samples: &[f32], sample_rate: f32) -> Self {
        let filterbank = build_mel_filterbank(40, 2048, sample_rate, 20.0, 16000.0);
        let mut planner = FftPlanner::new();
        let fft = planner.plan_fft_forward(2048);

        // Frame the audio with hop=512, window=2048
        let frames = frame_audio(samples, 2048, 512);
        let n_frames = frames.len();

        // Per-frame features
        let mut mfcc_frames = Vec::with_capacity(n_frames);
        let mut centroids = Vec::with_capacity(n_frames);
        let mut flatnesses = Vec::with_capacity(n_frames);
        let mut rolloffs = Vec::with_capacity(n_frames);
        let mut zcrs = Vec::with_capacity(n_frames);
        let mut rms_values = Vec::with_capacity(n_frames);

        for frame in &frames {
            let windowed = apply_pre_emphasis_and_window(frame, 0.97);
            let power = compute_power_spectrum(&windowed, &fft);
            let mel_energies = apply_mel_filterbank(&power, &filterbank);
            let log_mel = mel_energies.map(|e| (e.max(1e-10)).ln());
            let mfcc = dct_ii(&log_mel, 13);

            mfcc_frames.push(mfcc);
            centroids.push(spectral_centroid(&power, sample_rate));
            flatnesses.push(spectral_flatness(&power));
            rolloffs.push(spectral_rolloff(&power, sample_rate, 0.85));
            zcrs.push(zero_crossing_rate(frame));
            rms_values.push(rms(frame));
        }

        // Onset detection via spectral flux
        let onsets = detect_onsets(&mfcc_frames, sample_rate, 512);
        let onset_rate = onsets.len() as f32 / (samples.len() as f32 / sample_rate);
        let ioi_var = inter_onset_interval_variance(&onsets, sample_rate);

        // Aggregate statistics across frames
        AudioFeatureSet {
            mfcc_mean: mean_across_frames(&mfcc_frames),
            mfcc_var: var_across_frames(&mfcc_frames),
            centroid_mean: mean(&centroids),
            centroid_var: variance(&centroids),
            flatness_mean: mean(&flatnesses),
            rolloff_mean: mean(&rolloffs),
            zcr_mean: mean(&zcrs),
            rms_mean: mean(&rms_values),
            rms_var: variance(&rms_values),
            onset_rate,
            ioi_var,
        }
    }
}
```

### AD-4: Spectral feature formulas

All operate on the power spectrum `P[k]` of a single frame, where `k` is the bin index and `f[k] = k * sr / fft_size`.

**Spectral centroid** — weighted mean frequency (brightness):

```
centroid = Σ_k (f[k] * |X[k]|) / Σ_k |X[k]|
```

**Spectral flatness** — geometric/arithmetic mean ratio (tonality vs noise):

```
flatness = exp(mean(ln(P[k]))) / mean(P[k])
```

Result in [0, 1]. Near 0 = tonal (harmonic). Near 1 = noise (flat spectrum).

**Spectral rolloff** — frequency below which 85% of spectral energy lies:

```
Find smallest k_r such that Σ_{k=0}^{k_r} P[k] >= 0.85 * Σ_k P[k]
rolloff = f[k_r]
```

**Zero-crossing rate** — sign changes per sample (time-domain):

```
zcr = (1 / 2N) * Σ_{n=1}^{N-1} |sign(x[n]) - sign(x[n-1])|
```

### AD-5: Onset detection via spectral flux

```
flux(t) = Σ_k HWR(|X(k,t)| - |X(k,t-1)|)
```

where `HWR(x) = max(0, x)` (half-wave rectify — only count energy increases).

Peak picking with adaptive threshold:

```
onset at t if:
  flux(t) > median(flux(t-5..t+5)) + 0.1 * max(flux)
  AND flux(t) >= flux(t-1) AND flux(t) >= flux(t+1)  (local max)
  AND t - last_onset > min_ioi  (30ms minimum inter-onset interval)
```

**Inter-onset interval variance** — captures rhythmic regularity:

```
ioi = [onset[1]-onset[0], onset[2]-onset[1], ...]
ioi_var = variance(ioi)
```

Low IOI variance = metronomic (TBLK). High = rubato or random (DRON has no onsets, so IOI is undefined → set to a high sentinel value).

### AD-6: HeadlessOrganismRenderer — exploiting existing OrganismDsp

`OrganismDsp::from_dna(&dna, sr)` already works headless. The renderer is a thin wrapper:

```rust
pub struct HeadlessOrganismRenderer {
    sample_rate: f32,
}

impl HeadlessOrganismRenderer {
    pub fn new(sample_rate: f32) -> Self {
        Self { sample_rate }
    }

    /// Render mono audio from DNA. Duration in seconds.
    /// Sends a NoteOn at t=0 to trigger enveloped cells.
    pub fn render(&self, dna: &OrganismDna, duration_secs: f32) -> Option<Vec<f32>> {
        let (mut dsp, _handles) = OrganismDsp::from_dna(dna, self.sample_rate)?;

        // Trigger note-on for cells that need it (timbre_voice, strike_voice)
        dsp.handle_command(DspCommand::NoteOn { freq: 0.0, velocity: 0.8 });

        let num_samples = (duration_secs * self.sample_rate) as usize;
        let mut output = Vec::with_capacity(num_samples);
        let mut frame = [0.0f32; 2];

        for i in 0..num_samples {
            dsp.tick(&mut frame);
            output.push((frame[0] + frame[1]) * 0.5); // stereo → mono

            // For pattern-gen organisms, the clock ticks automatically.
            // For envelope-based organisms, retrigger periodically to keep sound active.
            // Retrigger every 0.5s for sustained evaluation window.
            if i > 0 && i % (self.sample_rate as usize / 2) == 0 {
                dsp.handle_command(DspCommand::NoteOn { freq: 0.0, velocity: 0.8 });
            }
        }

        Some(output)
    }

    /// Render and extract features in one step.
    pub fn render_features(&self, dna: &OrganismDna, duration_secs: f32) -> Option<AudioFeatureSet> {
        let audio = self.render(dna, duration_secs)?;
        Some(AudioFeatureSet::from_audio(&audio, self.sample_rate))
    }

    /// Render N times and return averaged features (for stochastic stability).
    pub fn render_features_averaged(
        &self, dna: &OrganismDna, duration_secs: f32, n_renders: usize
    ) -> Option<AudioFeatureSet> {
        let feature_sets: Vec<AudioFeatureSet> = (0..n_renders)
            .filter_map(|_| self.render_features(dna, duration_secs))
            .collect();
        if feature_sets.is_empty() { return None; }
        Some(AudioFeatureSet::average(&feature_sets))
    }
}
```

**Key design choices:**

1. **NoteOn at t=0**: Enveloped cells (timbre_voice, strike_voice) need a trigger to produce sound. PatternGen self-triggers via its internal clock.
2. **Periodic retrigger every 0.5s**: Ensures sustained sound for feature extraction even if the envelope fully releases. Without this, a short-decay strike would be silent after 100ms.
3. **Stereo→mono downmix**: Feature extraction operates on mono. The `(L+R)/2` mix preserves energy.
4. **`_handles` discarded**: SharedHandles allow real-time param modulation, but headless rendering uses fixed DNA params — no live knob twiddling.

**Computation budget per evaluation:**

| Step | Time (44.1kHz, 3s audio) |
|------|--------------------------|
| `OrganismDsp::from_dna()` | ~0.1 ms (cell construction) |
| `tick()` × 132,300 samples | ~2-5 ms (depends on cell count) |
| `AudioFeatureSet::from_audio()` | ~1-2 ms (FFT + mel + DCT) |
| **Total per candidate** | **~3-8 ms** |

At 200 candidates × 100 generations = 20,000 evaluations × 5ms = **~100 seconds**. Well within the 2-5 minute budget.

### AD-7: Fitness function — normalized weighted Euclidean distance

```rust
impl AudioFeatureSet {
    /// Distance between two feature sets. Lower = more similar.
    /// Features are pre-normalized to zero mean, unit variance using population statistics.
    pub fn distance(&self, other: &Self, weights: &FeatureWeights) -> f32 {
        let mut d = 0.0f32;

        // MFCC mean distance (13 dims, weight 0.35)
        for i in 0..13 {
            let diff = self.mfcc_mean[i] - other.mfcc_mean[i];
            d += weights.mfcc_mean * diff * diff;
        }

        // MFCC variance distance (13 dims, weight 0.25)
        for i in 0..13 {
            let diff = self.mfcc_var[i] - other.mfcc_var[i];
            d += weights.mfcc_var * diff * diff;
        }

        // Spectral stats (4 dims, weight 0.15)
        d += weights.spectral * (self.centroid_mean - other.centroid_mean).powi(2);
        d += weights.spectral * (self.centroid_var - other.centroid_var).powi(2);
        d += weights.spectral * (self.flatness_mean - other.flatness_mean).powi(2);
        d += weights.spectral * (self.rolloff_mean - other.rolloff_mean).powi(2);

        // Temporal (3 dims, weight 0.10)
        d += weights.temporal * (self.zcr_mean - other.zcr_mean).powi(2);
        d += weights.temporal * (self.rms_mean - other.rms_mean).powi(2);
        d += weights.temporal * (self.rms_var - other.rms_var).powi(2);

        // Rhythmic (2 dims, weight 0.15)
        d += weights.rhythmic * (self.onset_rate - other.onset_rate).powi(2);
        d += weights.rhythmic * (self.ioi_var - other.ioi_var).powi(2);

        d.sqrt()
    }
}

pub struct FeatureWeights {
    pub mfcc_mean: f32,   // 0.35 / 13 = 0.027 per dim
    pub mfcc_var: f32,    // 0.25 / 13 = 0.019 per dim
    pub spectral: f32,    // 0.15 / 4  = 0.038 per dim
    pub temporal: f32,    // 0.10 / 3  = 0.033 per dim
    pub rhythmic: f32,    // 0.15 / 2  = 0.075 per dim
}
```

**Feature normalization**: Before computing distance, each feature dimension is normalized to zero mean, unit variance across the population. This prevents high-magnitude features (centroid in Hz, ~500-8000) from dominating low-magnitude features (flatness in [0,1]). The normalizer is computed from the initial random population and updated each generation.

### AD-8: Evolutionary search — CMA-ES with fallback to tournament GA

CMA-ES (Covariance Matrix Adaptation Evolution Strategy) is the state-of-the-art optimizer for continuous parameter spaces (Hansen 2006). It self-adapts the mutation distribution (full covariance matrix), discovering correlations between parameters. This is critical for organism DNA where `membrane_freq` and `bandwidth` are correlated — CMA-ES learns this automatically.

**Why CMA-ES over basic GA:**

| | Tournament GA | CMA-ES |
|-|---------------|--------|
| Mutation | Fixed isotropic Gaussian | Adaptive, correlated |
| Convergence | ~100-200 generations | ~30-80 generations |
| Param correlations | Ignored | Learned |
| Population size | 100-200 | 4 + 3*ln(N) ≈ 10-15 for N=9..21 |
| Tuning required | sigma, crossover rate | Almost none (self-adapting) |

**Fallback**: For dimensions > 50 (future complex organisms), CMA-ES covariance matrix becomes expensive (O(N²) space, O(N³) update). Fall back to separable CMA-ES or tournament GA.

**CMA-ES core loop:**

```rust
impl SoundTargetSearch {
    /// Run the search on the calling thread. Sends progress updates via channel.
    pub fn run(&mut self) -> SearchResult {
        let n = self.descriptors.len(); // parameter dimensions
        let lambda = if self.config.population_size > 0 {
            self.config.population_size
        } else {
            4 + (3.0 * (n as f32).ln()) as usize
        };
        let mu = lambda / 2; // parent count

        // CMA-ES state
        let mut mean = self.initial_normalized_params(); // from template DNA
        let mut sigma = self.config.initial_sigma;
        let mut C = DMatrix::identity(n, n); // covariance matrix
        let mut p_sigma = DVector::zeros(n); // evolution path (step-size)
        let mut p_c = DVector::zeros(n);     // evolution path (covariance)

        let mut best = SearchResult::default();
        let mut normalizer = FeatureNormalizer::default();

        for gen in 0..self.config.max_generations {
            // 1. Sample lambda candidates from N(mean, sigma² * C)
            let candidates = sample_multivariate_normal(&mean, &C, sigma, lambda, &mut rng);

            // 2. Clamp to [0,1] and evaluate
            let mut evaluated: Vec<(DVector<f32>, f32)> = candidates.into_iter()
                .map(|params| {
                    let clamped = params.map(|x| x.clamp(0.0, 1.0));
                    let dna = self.params_to_dna(&clamped);
                    let features = self.renderer.render_features(&dna, self.config.render_duration);
                    let fitness = match features {
                        Some(mut f) => {
                            normalizer.normalize(&mut f);
                            f.distance(&self.target, &self.config.weights)
                        }
                        None => f32::MAX, // failed render = worst fitness
                    };
                    (clamped, fitness)
                })
                .collect();

            // 3. Sort by fitness (ascending — lower is better)
            evaluated.sort_by(|a, b| a.1.partial_cmp(&b.1).unwrap());

            // 4. Update best
            if evaluated[0].1 < best.fitness {
                best.fitness = evaluated[0].1;
                best.dna = self.params_to_dna(&evaluated[0].0);
                best.features = self.renderer.render_features(&best.dna, self.config.render_duration);
            }

            // 5. CMA-ES update: new mean from top mu candidates
            let old_mean = mean.clone();
            mean = weighted_mean(&evaluated[..mu]);

            // 6. Update evolution paths and covariance (standard CMA-ES formulae)
            update_paths(&mut p_sigma, &mut p_c, &mean, &old_mean, &C, sigma, mu, n);
            update_covariance(&mut C, &p_c, &evaluated[..mu], &old_mean, sigma, mu, n);
            update_sigma(&mut sigma, &p_sigma, n);

            // 7. Report progress
            if let Some(ref tx) = self.progress_tx {
                let _ = tx.try_send(SearchProgress {
                    generation: gen,
                    best_fitness: best.fitness,
                    mean_fitness: evaluated.iter().map(|e| e.1).sum::<f32>() / lambda as f32,
                    best_features: best.features.clone().unwrap_or_default(),
                    best_dna: best.dna.clone(),
                    elapsed_secs: start.elapsed().as_secs_f32(),
                });
            }

            // 8. Early termination
            if best.fitness < self.config.fitness_threshold { break; }
            if sigma < 1e-8 { break; } // converged
        }

        best
    }
}
```

**Parameter ↔ DNA conversion (uses S16 normalized space):**

```rust
impl SoundTargetSearch {
    /// Extract all numeric params from template DNA as a normalized [0,1] vector.
    fn initial_normalized_params(&self) -> DVector<f32> {
        let mut params = Vec::new();
        for (cell_dna, cell_descs) in self.template.cells.iter().zip(self.descriptors_per_cell()) {
            for desc in cell_descs {
                let native = cell_dna.params.get(&desc.name).copied().unwrap_or(desc.default);
                params.push(desc.to_normalized(native));
            }
        }
        DVector::from_vec(params)
    }

    /// Write normalized [0,1] vector back into a DNA clone.
    fn params_to_dna(&self, normalized: &DVector<f32>) -> OrganismDna {
        let mut dna = self.template.clone();
        let mut idx = 0;
        for (cell_dna, cell_descs) in dna.cells.iter_mut().zip(self.descriptors_per_cell()) {
            for desc in cell_descs {
                cell_dna.params.insert(desc.name.clone(), desc.to_native(normalized[idx]));
                idx += 1;
            }
        }
        dna
    }
}
```

### AD-9: Multi-render comparison for stochastic organisms

For organisms with inherent randomness (pattern_gen seed variation, clock jitter), a single render is noisy. Multi-render averaging stabilizes the feature estimate:

| n_renders | Accuracy | Time per candidate |
|-----------|----------|--------------------|
| 1 | Fast screening (±15% feature variance) | ~5 ms |
| 3 | Good balance (±8% variance) | ~15 ms |
| 5 | Accurate (±5% variance) | ~25 ms |
| 10 | High confidence (±3% variance) | ~50 ms |

**Strategy**: Use n_renders=1 during search (speed matters), n_renders=5 for the top 10 candidates per generation (accuracy matters for selection), n_renders=10 for the final result (presented to user).

```rust
impl SoundTargetSearch {
    fn evaluate_candidate(&self, dna: &OrganismDna, accurate: bool) -> Option<AudioFeatureSet> {
        let n = if accurate { 5 } else { 1 };
        self.renderer.render_features_averaged(dna, self.config.render_duration, n)
    }
}
```

### AD-10: DatasetGenerator for neural estimator training

```rust
pub struct DatasetGenerator {
    renderer: HeadlessOrganismRenderer,
    registry: CellRegistry,
}

pub struct DatasetEntry {
    /// Normalized [0,1] parameter vector.
    pub params: Vec<f32>,
    /// Extracted audio features (38 dims).
    pub features: AudioFeatureSet,
    /// Species name.
    pub species: String,
    /// Cell type list (topology descriptor).
    pub cell_types: Vec<String>,
}

impl DatasetGenerator {
    /// Generate N random DNA variants for a given species, render audio, extract features.
    pub fn generate(
        &self,
        template: &OrganismDna,
        n_samples: usize,
        duration_secs: f32,
        rng: &mut impl Rng,
    ) -> Vec<DatasetEntry> {
        let descriptors = self.registry.descriptors_for_dna(template);
        let cell_types: Vec<String> = template.cells.iter().map(|c| c.cell_type.clone()).collect();

        (0..n_samples).filter_map(|_| {
            // 1. Randomize params in normalized space
            let normalized: Vec<f32> = descriptors.iter()
                .map(|_| rng.gen::<f32>())
                .collect();

            // 2. Write to DNA
            let mut dna = template.clone();
            let mut idx = 0;
            for (cell_dna, cell_descs) in dna.cells.iter_mut().zip(descriptors_per_cell(&descriptors, template)) {
                for desc in cell_descs {
                    cell_dna.params.insert(desc.name.clone(), desc.to_native(normalized[idx]));
                    idx += 1;
                }
            }

            // 3. Render and extract features (multi-render for stability)
            let features = self.renderer.render_features_averaged(&dna, duration_secs, 3)?;

            Some(DatasetEntry {
                params: normalized,
                features,
                species: template.species.clone(),
                cell_types: cell_types.clone(),
            })
        }).collect()
    }

    /// Save dataset to JSON lines (one entry per line, numpy-compatible via serde).
    pub fn save_jsonl(&self, entries: &[DatasetEntry], path: &Path) -> io::Result<()> {
        let file = File::create(path)?;
        let mut writer = BufWriter::new(file);
        for entry in entries {
            serde_json::to_writer(&mut writer, entry)?;
            writeln!(writer)?;
        }
        Ok(())
    }
}
```

**Dataset sizes per species:**

| Species | Params | Recommended N | Render time (3s × 3 renders) | Total time |
|---------|--------|---------------|-------------------------------|------------|
| TBLK | 9 | 2,000 | ~15 ms each | ~30 s |
| DRON | 9 | 2,000 | ~15 ms each | ~30 s |
| MELO | 21 | 10,000 | ~25 ms each | ~4 min |

SpiegeLib literature recommends ~10× the parameter count for training. MELO's 21 dimensions warrants 10,000 samples. TBLK/DRON's 9 dimensions are fine with 2,000.

Output format: JSON lines. Each line is a `DatasetEntry` with `params` (Vec<f32>) and `features` (AudioFeatureSet). Compatible with Python/numpy via `json.loads()` per line. Future S17b can load these for `candle`-based neural estimator training.

**Apply mechanism — hot-swap DNA without audio glitch:**

1. User clicks "Apply Best"
2. System creates new `OrganismDsp::from_dna(&best_dna, sr)`
3. Crossfade: fade out current organism over 512 samples, fade in new over 512 samples
4. Swap `OrganismDsp` instance in the audio callback via atomic pointer swap or ring buffer message
5. Push old DNA to undo stack

```rust
pub enum AudioCommand {
    // ... existing variants ...
    /// Hot-swap organism DSP. Old DSP fades out, new fades in.
    SwapOrganism {
        org_index: usize,
        new_dna: OrganismDna,
        crossfade_samples: usize, // default: 512 (~12ms at 44.1kHz)
    },
}
```

The audio callback handles this without allocation:
1. Construct new `OrganismDsp` on the control thread
2. Send via ring buffer to audio thread
3. Audio thread crossfades over `crossfade_samples`
4. Old DSP is dropped on next cycle

### AD-12: Parallelism — evaluate candidates concurrently

Candidate evaluation is embarrassingly parallel (each is independent). Use `rayon` or `std::thread::scope` to evaluate the population concurrently:

```rust
use rayon::prelude::*;

let evaluated: Vec<(DVector<f32>, f32)> = candidates.par_iter()
    .map(|params| {
        let dna = self.params_to_dna(params);
        let renderer = HeadlessOrganismRenderer::new(self.renderer.sample_rate);
        let features = renderer.render_features(&dna, self.config.render_duration);
        let fitness = features.map(|f| f.distance(&self.target, &weights)).unwrap_or(f32::MAX);
        (params.clone(), fitness)
    })
    .collect();
```

On a 8-core machine with population λ=12, this evaluates the entire population in ~1 candidate's time. 100 generations × 5ms = **~0.5 seconds** total. Even without parallelism, 100 × 12 × 5ms = 6 seconds.
